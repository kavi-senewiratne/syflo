Branch creation — where the pause comes from, and what to show during it

Selecting text and clicking “Open as new chat” takes a visible moment before the branch appears. Measured in the running app on 2026-08-08 (Gemini Flash, PDF selection): the whole chain after the click is ~40 ms of real work — creating the chat, saving the highlight, refreshing the tree, opening the chat. The wait is one single call: the passage-title lookup that awaitTitle blocks on.

That lookup starts when the popup opens, so it is often already finished by the time the user clicks — then branching is instant (85 ms end to end, also measured). Click straight away and you wait out whatever is left of it, capped at TITLE_WAIT_MS = 2500. So the delay is real but conditional: it depends on how fast the user clicks and how fast the model answers.

02Option A — the button says it is working
Smallest change: the popup stays put, the primary button turns into a spinner and both buttons stop accepting clicks. Nothing about the branch logic moves — the title is still finished before the chat is created, so the tree never shows a placeholder. Press “Play the wait” to feel the real timings.

03Option B — open first, name the branch a moment later
The click no longer waits for anything: the popup closes at once, the branch appears in the tree and the chat opens. Only the title is still pending, shown as a shimmering placeholder that fills in when the lookup lands. This keeps the 2026-08-02 rule intact — the tree never shows the raw passage, it shows nothing at all until the real title arrives.

04Is it worth building?
Three honest options, including doing nothing. Below 1 s a spinner can read as busier than the wait it covers — which is why “nothing” is on the table at all.

05What I need from you before building

Decisions

  1. Which option? A is a 20-minute change and keeps every current guarantee. B removes the wait outright but introduces a titleless moment.
  2. If B: what fills the gap? The shimmering placeholder shown above, or a neutral word like “New branch” that gets replaced. The placeholder respects the 2026-08-02 rule more literally.
  3. A and B are combinable. B for the tree, plus A’s spinner for the rare case where even chat creation is slow (offline backend). Say so if you want both.
