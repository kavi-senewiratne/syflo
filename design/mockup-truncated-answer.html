Truncated answers, overloaded providers, honest chapters

Measured on 2026-08-16: a Video overview stopped mid-word after 340 completion tokens (usage_log), the chapter list showed a single chapter, and nothing in the UI said anything was wrong. A probe against the same prompt returned finish_reason=stop once and HTTP 503 “high demand” five times out of six — the provider drops requests under load, and llm.js retries none of them (maxRetries: 0, deliberately, so the route owns retry policy). Three states are missing from the app: an answer that ended early (01), a chapter list that knows why it is short (02), and an overloaded provider that Syflo silently retries (03). Card language, buttons and gray meta rows are taken unchanged from mockup-model-flow.html §05/§11 and mockup-quota-states.html §09/§10 — nothing new is invented here, the existing vocabulary is applied to a new cause.

01 The answer stopped early new

Today a truncated answer is indistinguishable from a finished one: tools.js spots it (finish_reason ≠ stop) but only writes a console.warn. The reason travels to the client already — inside the perf event — so the fix is to persist it on the message and render the same card the failReason states use, placed under the answer instead of replacing it: the text that did arrive is worth keeping. Continue is the primary exit; it re-asks with the answer so far and the last time mark, so the model resumes at the section boundary rather than starting over. Regenerate stays available for the case where the beginning is not worth keeping.

02 The chapter list knows its own state replaces current empty state

Today the pane has exactly one fallback: “Die Kapitel sind die Abschnitte der Video overview. Frag nach der Übersicht, dann stehen sie hier.” — advice that was already wrong when it shipped, because structurePrompt() sends that question automatically on import. The pane does not know whether an answer is streaming; it only receives overview. Passing the streaming state turns one wrong sentence into three true ones. The truncated state is the one that answers the user's actual question — “why does it stop at 5:12?” — and it carries the same Continue button as §01, because the chapter list is where the gap is noticed.

03 The provider is overloaded — Syflo retries, visibly new

HTTP 503 “This model is currently experiencing high demand” is not a quota and not a key problem: the same request works seconds later. Today it falls straight through if (!isRateLimit(err) && !tooLarge && !unavailable) throw err into a *Failed* card that blames nothing in particular. The fix is a third branch in the route's retry loop: up to three attempts with a growing pause (2 s, 4 s, 8 s), and the wait is shown, not hidden — the same amber chip the rate-limit wait already uses (mockup-quota-states §09), only its copy differs. No cooldown is remembered: overload is a passing weather condition, not an exhausted budget, and marking the model unusable would push the user down the ladder for nothing.

04 The seam the join cannot verify new

Live incident 2026-09-07: the answer broke off at * Nur , the continuation opened with der Normalverteilungsannahme erfüllt ist — no repeated words, a jump past the middle of the answer — and the blind join produced a garbled sentence with a silent gap. The repeated opening words are the seam's only proof; when they are missing AND the old text stops mid-sentence AND the continuation starts with a word character (a leading space is itself evidence of a deliberate continuation), the round is discarded and retried once (variant C, user decision 2026-09-10). A second unverified round is appended anyway — half the answer beats none — but flagged seam_suspect, and the card below the answer says so. Its exit is Regenerate: continuing cannot repair a middle that is already welded together wrong.
