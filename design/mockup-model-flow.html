Model flow v3 — no dead ends

Companion to mockup-quota-states.html (whose cards 04/05/08 stay as built). This file closes the gaps the 2026-07-26 audits found in the full journey “rate limit → switch model → local model”. Audit pass 2 (three parallel code audits, same day) verified every state against the built code and found five more dead ends — §01 now carries a verified status per row (built / partial / missing), and §09–§11 close the worst of the new finds: the Interrupted dead end, silently lost questions, and the local→cloud privacy leak.

Two invariants for every state: (1) at least one button that actually leads out — never a retry that fails identically; (2) the information budget of copy v3: one message line, at most one info line, a button row, one footnote — explanations live in tooltips.
Implementation status (2026-07-26, same day): ALL sections §02–§11 are built (TDD; backend 461 + frontend 567 tests green; open decisions resolved as drawn). The §01 status pills document the pre-build audit state and stay as the record of what was broken. Additions beyond this file during the build: the queued note's “N Anfragen davor” is a LINK to the chat being answered right now (user request); failReason gained local_unreachable (Ollama down ≠ model missing); §08's image-pool clock ships as per-kind retryAt (daily clock from daily cooldowns — the vision-pool distinction is unobservable because all daily cooldowns share the same UTC-midnight reset).

07 Queue transparency — cloud parallel, local FIFO, visible model built 2026-07-26

Audit: the FIFO is global — a sub-second Gemini question waits behind a minutes-long local generation, and a model switch silently applies to queued messages. The decided split finally ships: cloud requests run in parallel (providers rate-limit server-side), only local jobs queue (one KV slot). The queued note gains a model chip, so the “which model will answer this?” question — and any switch while waiting — becomes visible instead of silent.

08 Honest promises for image questions built 2026-07-26 · via per-kind retryAt

Audit: with an image attached, failover skips text-only models — correct — but retryAt is computed over all cooling models, so the countdown can promise a retry that a text-only model’s recovery will never satisfy. Fix: for image requests, retryAt and the “all exhausted” decision consider only vision-capable candidates, and the card copy names the real pool. Audit 2 found two more broken promises under the same rule: the daily card’s clock must come from the daily cooldown’s expiry, not the global minimum (a sibling model’s 90 s cooldown currently turns the daily card into a contradiction — daily copy, no clock line, disabled 90 s countdown); and “Limit erhöhen” must open the billing page of the provider that hit the limit (carried in the SSE error), not blindly the active one — after a cross-provider failover they differ.

09 Interrupted gets an exit built 2026-07-26

Three paths lead into *Interrupted*: the Stop click, a reload mid-answer, and a connection drop. Today the row is a dead end — no retry in the UI, and the regenerate endpoint rejects the marker (only *Failed* is accepted). Worse, the paths disagree: a connection drop persists *Interrupted* on the backend while the frontend shows a *Failed* row whose retry runs into a 409 → a fresh failed row → forever. And a Stop during a rate-limit wait persists *Failed* although the UI says “Unterbrochen”. Fix: one truth, one exit — every abort path persists *Interrupted*, the row always carries a retry, and regenerate accepts both markers.

10 Nothing gets lost — persist at enqueue built 2026-07-26

Two silent-loss paths found: (a) reload/close while queued — the user message is persisted only at dequeue, so the question a user typed minutes ago vanishes without trace (its uploaded attachments stay as orphans); (b) failure in a background chat — no marker is persisted and the visible-chat guard drops the patch, so the question just sits there unanswered, with no retry and no explanation. Fix: persist the user message at enqueue; any persisted question whose answer never arrived renders one quiet row. (Canceling while queued still deletes the question — an explicit stop stays “counts as never asked”, only silent losses change.)

11 Privacy guard — failover never leaves Lokal silently built 2026-07-26

The worst find of the audit: with the local provider active, a missing/mistyped/removed Ollama model 404s, and the failover ladder — which only knows cloud candidates — silently ships the question including the paper context to Google/Groq, under the wrong note “Kontingent bei ollama erschöpft”, and a 24 h in-memory cooldown keeps redirecting to the cloud even after the model is re-pulled. New rule: automatic failover never crosses the local→cloud boundary. Cloud remains one explicit, named click away. (Cloud→cloud failover stays silent as designed — the privacy promise only binds the local provider.)

Consolidated backend contract (all sections): SSE error + persisted marker gain failReason: 'no_key' | 'bad_key' | 'no_vision' | 'network' (§05/§06); settingsChangedAt generalizes modelSwitchedAt — model switch, provider switch and key save all re-arm retry (§05); regenerate accepts *Interrupted* and every abort path persists it (§09); user messages persist at enqueue, background failures persist their marker (§10); failover never local→cloud, no 24 h cooldown for local models, reason-true failover notes (§11); per-reason and vision-aware retryAt + limit-hitting provider (with its billingUrl) in the error payload (§08); /api/quota-cooldowns consumed unfiltered (§02); queue split per provider kind + a generation timeout so one hung call cannot stall the FIFO (§07); prompt hygiene: *Failed*/*Interrupted* markers are filtered out of LLM history and branch ancestor transcripts.
