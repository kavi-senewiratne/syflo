Sidebar — pinned chats in their own section at the top

The root list is grouped into relative date sections today (“Today”, “Yesterday”, …). A chat you return to every day sinks out of those sections as soon as newer chats arrive, and the only way back is scrolling or reading titles.

A pinned chat leaves the date grouping and moves into one section of its own, above every date section. The section is announced exactly the way the date sections are — the same 11 px uppercase label — with a pin icon in front of it. The rows themselves carry no per-row marking: the heading already says what they are (user decision 2026-08-11).

The rule. Pinning changes where a root chat is listed, nothing else. The section only exists while at least one chat is pinned; a pinned chat appears in no date section; the rows keep the identical geometry, PDF/YT tags, streaming dots and active pill they have today — and no control of their own: pinning and unpinning are both the right-click menu. Colors stay in the standard token families (gray-* for the label, blue-* for the active row), so all five themes remap them.

What this implies for the code.
  • chats.pinned_at (TEXT, nullable) — one migration in backend/database.js. A timestamp rather than a flag, so the pinned section can order itself most recently pinned first without a second column.
  • PATCH /api/chats/:id gains pinned — the same endpoint that renames.
  • groupChatsByDate.ts stays untouched; the pinned roots are split off before it is called, so a pinned chat never appears twice.
  • Only ROOT chats can be pinned — the section lists roots, and a pinned branch would have no tree to sit in. The expanded single-tree view is unaffected.
  • Strings: sidebar.pinned / sidebar.pin / sidebar.unpin, EN and DE in frontend/src/strings.ts (“Angepinnt”, “Chat anpinnen”, “Nicht mehr anpinnen”).
  • Keyboard navigation (ADR-0011) needs nothing new: the pinned rows are ordinary data-focus-item rows and come first in DOM order.
