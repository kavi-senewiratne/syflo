/branch — a branch from a typed topic

Today every branch is born from a selection: mark a passage, click “Open as new chat”. /branch <topic> is the other door — you type what you want to go into, and the branch appears in the tree with that topic as its first question. Nothing is selected, so the branch has no parent quote and no highlight kind.

The open decision is the one you named: where does that branch hang? Under the chat you are standing in, under the root of the tree, or wherever you point it. Section 02 shows all three next to each other.

Carried over from /btw — same family, same rules

  • The command is recognised only at the start of the line, so “/branch” inside a quote or URL stays plain text.
  • The chip is named after the command — /branch in both app languages, not a translated noun.
  • A bare /branch with no topic does nothing on Enter — it is a half-typed command, not an empty branch.
01The gesture — three beats

Typing /branch swallows the command into a chip, exactly like /btw. The difference is the chip’s right half: it names the parent the branch will hang under, so the answer to “where does it land?” is on screen before you press Enter — never a surprise afterwards.

Current chat on top, then the tree in its own order. No search field — a tree that needs one is bigger than this command is for.

  • My recommendation: C with A as the default. The default keeps the one rule the app already has — a branch grows where you stand — and the chip makes the exception one click away, visible before you send. B as a fixed rule is the only variant that can surprise you.
  • What is at stake is context, not tidiness. Under the current chat the new branch inherits that chat’s verbatim transcript; under the root it inherits only the source. If the topic came out of what you were just reading, A is the cheaper and better prompt.
  • The mind map does not care. Both A and B produce a normal node — the layout (rows and lanes) already handles either depth.

  • Recommendation: A. It is the same shape as the Video overview — an auto-sent visible message that gets the branch started. B leaves the map with a node whose second line is a placeholder until you return to it.
  • A does not lock you out. The auto-sent message is an ordinary user message; you can keep asking in the same branch straight away.
04What a typed branch does not have

A selection branch carries two things a typed one cannot: the parent quote it was cut from, and the highlight kind that colours its node. Neither is faked here — the node simply has no colour bar, and the header shows only the parent link.

06What I need from you before building
  1. Attachment point — A, B or C? If C: is the default really the current chat, or should the picker open with the root preselected when you are deep in the tree?
  2. Auto-send the topic (§03 A) or open empty (§03 B)? A costs one LLM call per /branch; B leaves the map node without an outcome line.
  3. What is the topic worth as a question? Send it verbatim (“positional encodings”), or let the branch prompt turn it into a real question (“Explain positional encodings in this paper”)? The second reads better but is the app putting words in your mouth.
  4. Does /branch work in the root chat too? There it is simply a first-level branch — I would allow it, but then the chip’s target line says the root’s own title, which reads slightly odd.
  5. Anything for Tab? /btw has no completion today. If /branch gets the target picker, Tab could jump into it — or we keep both commands completion-free and consistent.
