Content search — find in tree & search across chats

Today the only way to re-find a word is scrolling: through a long answer, through a 90-minute transcript, or through the sidebar's chat titles. This mockup covers two different searches that must not be confused: finding a word inside the tree that is open (chat turns, transcript, chapters — the Cmd+F gesture), and finding which chat ever talked about something (a global search across all trees).

Sections 01–03 are the global search, 04–07 the in-tree find. All frames use the query gradient so the same word appears in chat prose, transcript lines, a chapter title, code and math — the places a real match lands.

The rule. One highlight vocabulary everywhere: every match is tinted amber-100, the current match amber-300 with an amber-500 ring — amber, because blue-* already means selection and the user's own saved highlights. ⌘F opens the in-tree find, ⌘K the global search; Enter/⇧Enter walk forward/backward through the matches of the same word, Esc closes and removes every mark. Colors stay in the standard token families so all five themes remap them.

02 Global search — anatomy of a hit

Whatever the entry point, a hit must answer three questions before it is clicked: which chat, which kind of text (question, answer, branch, transcript line, chapter, title), and which words around the match. Grouping is always by tree; inside a group, hits keep document order. Clicking a hit opens the chat and lands on the match with the same amber mark and the existing jump-flash — a transcript hit seeks the video, a branch hit opens that branch.

03 Find in the open tree — the bar (⌘F)

Inside a tree, search is a find bar, not a result list: the text stays where it is and the matches light up in place. Two candidate placements. Both carry the same controls: the field, the match counter 3/17, prev/next chevrons, an Aa toggle for case-sensitive matching (off by default), and close.
A floating bar, top right
Browser-style: a small floating bar over the chat column's top-right corner. Covers no layout, appears/disappears instantly, and the eye already knows this pattern from Chrome/VS Code.

Why does batch norm help with exploding gradients?

Normalising each activation keeps the gradient of the loss in a predictable range: the backward pass multiplies layer Jacobians, and without normalisation those products drift exponentially.

With BN, the gradient w.r.t. γ and β stays bounded, which is why deeper nets suddenly trained in 2015. The gradient noise from the batch statistics even acts as a mild regulariser.

The bar overlaps at most one line of the first message; scrolling happens under it. 3/17 updates live while typing — deleting a character re-counts immediately.
B docked row under the header
The bar becomes a full-width row between header and messages, pushing content down. Nothing is ever covered, and there is room for scope chips (section 05) without crowding.

04 The same word in many places — walking the matches

The explicit requirement: all occurrences of the same word must be findable, one after the other. Every occurrence is marked at once (amber); exactly one is the current match (darker, ringed). Enter or ∨ jumps to the next, ⇧Enter or ∧ to the previous, wrapping around at the end — the counter flips from 17/17 back to 1/17. Each jump scrolls the match to mid-viewport and reuses the existing jump-flash so the eye lands correctly.
A counter + jump only

05 One tree, three text bodies — scope chips

In a YouTube tree the open view holds chat turns, the transcript pane and chapter headings; a PDF tree holds chat turns and the document. ⌘F must not silently search only one of them. The find bar carries scope chips with live counts; “Alle” is the default, and Enter-walking crosses pane boundaries in reading order (chat turn → transcript line → chapter heading, by document position). A transcript match scrolls the transcript pane and offers the timestamp; clicking the timestamp seeks the video, exactly like a citation jump.

06 Edge cases in the running text

The cases that decide whether the feature feels solid. Each frame shows the behaviour, the verdict says the rule.
1 match inside math or code
gradient appears inside a KaTeX formula (as \nabla-adjacent prose) and inside a code block. Code is markable; rendered math is never re-wrapped — a mark inside KaTeX output breaks its boxes, the same reason branch links skip formulas.
Batch normalisation — read-through

The update follows the gradient:

θ ← θ − η ∇θ L(θ)
loss.backward()  # accumulates gradients into .grad

…where the formula's gradient is the ∇ term above.

Math is skipped for marking but not for counting: a formula-only hit gets an amber left-edge bar on the whole formula block instead of an inline mark, so the jump still has a target. Reuses the segment list from markdown/branchLinks.ts.
2 case, umlauts, word split by markdown
Default matching is case-insensitive and diacritic-exact (Übergang ≠ Ubergang — folding umlauts would surprise a German corpus more than it helps). A word that markdown split into two inline boxes (bold half + plain half) still counts as one match.

What this implies for the code.
  • Global search: one SQLite FTS5 virtual table over messages.content, videos.transcript (per line, keyed by timestamp), chapter headings and chat titles, kept in step by triggers in backend/database.js; GET /api/search?q= returns hits grouped by root chat with snippet() context. Substring queries use the trigram tokenizer so gradient also finds Gradientenabstieg.
  • In-tree find: pure frontend. Matching over the rendered panes' text content, marking via the CSS Custom Highlight API (ranges, no DOM rewrapping — streaming stays cheap); the math/code segment list from markdown/branchLinks.ts is reused to skip KaTeX output.
  • Jumps reuse the existing machinery: mid-viewport scroll + unified flash (project_syflo_flash_unified) in the tree, quote_highlight_id-style landing when a global hit opens a chat, video seek for timestamp hits.
  • Keyboard (ADR-0011): ⌘F find-in-tree, ⌘K global, Enter/⇧Enter next/previous with wrap-around, Esc closes and clears. The find bar is a focus zone; Esc from it returns focus to the composer.
  • Strings: search.* EN/DE pairs in frontend/src/strings.ts („Keine Treffer", „n weitere Treffer", „Mindestens 2 Zeichen eingeben", chip labels).
  • Non-goals for v1: regex, whole-word toggle, search inside PDF pages (the PDF text layer has its own selection quirks — own mockup when it becomes real).
