Clicking a quote jumps back to its source

A user message that carries an “Ask in chat” quote today renders that quote as dead text (MessageBubble.tsx, data-testid="user-message-quote"). The passage it came from — a PDF highlight, a highlight in the parent chat, or a highlight in this very chat — is still on record as a MessageHighlight / Highlight row, but nothing connects the two on screen.

Syflo already speaks this gesture once: the “Branched from …” link in the branch header jumps to the passage a branch was opened from (branchSource.ts, mockup-branch-header.html). This mockup applies the same gesture to the quote inside the bubble, and shows three ways it could look.

01 Today — the quote is dead text
The bar and the dimmed text say “this is quoted”, but there is nowhere to go. To find the passage again the user scrolls the parent chat or the PDF by hand.

02 Variant A — the quote itself is the link
The whole quote block becomes clickable. On hover the bar thickens, the dimming lifts to full opacity, a faint tint fills the block, and a small corner-up-left icon appears at the end of the text. Nothing new is added to the bubble — the element that is already there simply gains a behaviour.

03 Variant B — a source chip above the quote
A small pill above the quote names where the passage came from, and only that pill is clickable. This is the only variant that answers the second question a user has — “from which paper / which chat?” — and it leaves the quote text fully selectable.

05 Where the click lands
Identical to the existing jump from the highlights drawer and the branch header: scroll the passage into view, then flash its highlight for ~1.4 s. PDF source → the PDF pane scrolls to the page. Chat source → the message column scrolls; if the passage lives in the parent chat, the parent-context pane opens instead of switching chats.

06 What it costs to build

The blocker: the quote carries no anchor today

  • The quote is stored inside the message text as markdown blockquote lines and parsed back out by splitLeadingQuote(). The message row knows nothing about the highlight it came from.
  • The highlight, on the other hand, already exists: handleAskInChat() creates a MessageHighlight for every chat selection, and a PDF selection with a colour saves a Highlight. What is missing is the link from the sent message back to that row.
  • Smallest honest change: carry the highlight id in ComposerQuote, persist it on the message (quote_highlight_id + quote_kind = 'pdf' | 'chat'), and reuse branchSourceJump()-style resolution to turn it into a jump.
  • PDF quotes without a colour save no highlight at all (deliberate, 2026-07-21) — those quotes stay unclickable unless that rule changes.
  • Messages sent before this feature have no anchor: they render exactly as today. No migration, no guessing by text matching.
Decided and built (2026-08-08): Variant A. The quote itself is the link — nothing is added to the bubble, only behaviour. Implementation notes: one column messages.quote_highlight_id, no quote_kind (the tree-highlight list resolves PDF vs. chat and doubles as the “does the source still exist?” check); role="button" instead of a real <button>, so the quote text stays selectable and “Ask in chat” on a quote keeps working; a click that ends a selection is not a jump. The started SSE event carries the anchor too — without it the just-sent quote was clickable only after a reload, which no test caught.

Runner-up was variant B (source chip): the only one that also answers “from where?” and the only one with an honest disabled state for deleted sources. Worth revisiting if users ask which paper a quote came from.
