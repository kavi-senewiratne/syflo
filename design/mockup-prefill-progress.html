Prefill progress — honest ETA while the model reads the source

Ollama exposes no live prompt-processing progress (ollama#6029), so Syflo shows an estimate: uncached tokens ÷ measured prefill rate (EMA over past cold answers, start value ~300 tok/s from the 2026-07-25 M4 Pro benchmark). The estimate is marked with “~” and degrades gracefully when it overruns. Colors/typography use standard theme tokens (--syflo-think-a for the bar, muted grays for text) so all five themes restyle it.

01 ETA line in the thinking indicator BUILD SPEC
The chosen variant. Appears under the bouncing dots only when the backend predicts ≥ 4 s of prefill (SSE event prefill). Counts down once per second; the 3px bar fills linearly. If the estimate runs out, the text switches to “taking a bit longer” and the bar stays full but keeps pulsing — no fake 99 %. Vanishes with the first token. German: “Quelle wird eingelesen… noch ~35 s” / “… dauert etwas länger”.
