Sidebar tree — highlight the connector path to the active chat

Selecting a deep branch should make its link back to the root visible at a glance. The chosen treatment colors only the connector lines on that path — rows keep today's styling, so a deep tree never turns wholesale blue. (Two earlier variants were rejected: tinting the ancestor rows, and a left accent bar on each ancestor row.)

All three states below use the same real tree so the rules are directly comparable.

The rule that makes this correct. A trunk segment is anchored inside a child's wrapper, but it belongs to the parent's spine: for a non-last sibling it spans that child's entire subtree so the following siblings can hang off it. So the run that actually reaches the on-path child is every earlier sibling's trunk in full, plus the on-path child's own trunk down to its elbow — and nothing below that elbow, which serves unrelated later rows. Only the on-path child's elbow turns; an earlier sibling carries the vertical run but its own row is off the path, so its elbow stays neutral.

Implementation. Sidebar/index.tsx computes the root→active id chain (findPathToId) and passes it down as activePathIds. ChatTree.tsx derives, per node, the index of the single child that is on the path and colors accordingly:
  • child index < pathIndex → whole trunk colored, elbow neutral
  • child index === pathIndex → elbow colored; trunk colored down to the elbow, split off a neutral tail when it is not the last sibling
  • child index > pathIndex, or no path → unchanged
Stacking matters. The elbow is 14px wide and reaches 6px past the row's left edge, so the row must sit above the connectors (position: relative; z-index: 1 on .node-row) — otherwise the line is painted straight into the selected or hovered pill. Rows without a background still show the full elbow, unchanged. Colors come only from the standard token families the :root[data-theme] blocks remap (blue-400 for the path, slate-300 for the default), so every theme recolors the highlight with its own accent. Widths stay on the hairline device-pixel snap, doubled for the path so it reads as deliberate at any zoom.
