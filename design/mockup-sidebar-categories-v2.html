Sidebar categories — the assembled design

Round 2. The five forks of mockup-sidebar-categories.html are decided; this page is the build blueprint: one complete sidebar with all four row types in place, the collapse states, the menus, and the geometry to build against.

Superseded in part, same day. Two rules on this page were reversed after seeing them in the running app, and design/mockup-sidebar-timeline-group.html holds the current state: (1) filing now outranks pinning — a chat that is both is listed only in its category, because the opposite made dragging a pinned chat into a category look broken; and (2) a category is no longer a 13 px row but an 11 px uppercase heading in gray-500 with its folder, matching the timeline parent, its subcategories in gray-400 — and with that, no chat row is indented anywhere. Also dropped: the header's folder-plus button and the “this category is empty” hint. Everything else below still holds.
Decided (user, 2026-08-16).
  1. §01 → B. A category is a 13 px row with a chevron, a folder icon, its name and a count — same pill, same hover as a chat row.
  2. Plus: the pin icon returns. The Pinned heading gets its pin back — reversing the 2026-08-11 decision, whose reason (“no section carries a symbol”) stops being true the moment category rows carry folders.
  3. §02 → C. A subcategory is not a row but an 11 px uppercase heading inside the open category. Its chats stay in the same column as the category’s own chats, so no row is ever indented twice.
  4. §03 → A. A chevron is always visible, left, on every collapsible thing — Pinned, categories, subcategories and the date sections. The whole row is the hit target.
  5. §04 → A. Categories replace the date sections for the chats in them. Order: Pinned → categories → everything uncategorised, still grouped by date.
  6. §05 → all three, minus one. Chat menu, category menu, drag-and-drop, empty state and inline naming all ship — but “Collapse all” is dropped.
What B + C together mean. Level one and level two are now deliberately different kinds of object: a category is a row you can hover, count and open a menu on; a subcategory is a label. Three consequences to accept up front — a subcategory has no “…” button (right-click only, like the date headings), no folder icon, and “New category” and “New subcategory” are two separate commands in two separate menus rather than one command at two depths.

§04 · What this asks of the existing code

Rules this breaks or bends

  • “No section carries a symbol” (2026-08-11) is reversed for Pinned, by decision. The comment in Sidebar/index.tsx:503 must be rewritten, not deleted — it records why the pin left, and now why it came back.
  • “No control on the row” (2026-08-11) still holds for chats. Category rows get a “…”, and that is the one row type where it doesn’t hold. It appears on hover only and replaces the count, so nothing moves.
  • Keyboard (ADR-0011). Categories and headings become data-focus-items; rows hidden by a collapse must leave that walk entirely. ← / → are region switches today — if they are to close and open, that collides.

Data

  • New table categories: id, name, parent_id (nullable, self-reference), position, collapsed, created_at. A subcategory is a category with a parent.
  • One nullable category_id on chats, pointing at either level.
  • The two-level cap is enforced on creation: a category whose parent_id is set may not be given children. Nothing in the schema prevents it.
  • The collapse state of the date sections has no row to hang off — it belongs in the same user state as the sidebar’s collapsed flag.
  • Deleting a category sets category_id = NULL on its chats and deletes its subcategories the same way. foreign_keys is ON in better-sqlite3, so the cascade must be spelled out.

Themes

  • The folder and pin icons are gray-400, the count gray-400, the drop ring blue-400 on blue-50 — all five themes remap them.
  • The divider between categories and dates is gray-100, the same as the one already under the tree view.
  • Matrix renders gray-100 almost invisibly. The divider and the empty-category hint are the two places to check there before calling it done.
Resolved while building (2026-08-16), all three as this page shows them.
  • Pinned versus categorised: Pinned wins. A chat that is both is listed only at the top — one chat, one place, consistent with §04-A. Filing a pinned chat therefore has no visible effect until it is unpinned.
  • The active chat does NOT force its section open. A section the user closed stays closed and the sidebar simply shows no active row; the chat header says where you are.
  • “New category” lives in the sidebar header, a folder-plus next to the new-chat button. It has to be reachable with no category yet, and the chat menu’s “New category…” only exists once you right-click a chat.
  • “New category…” in a chat’s menu FILES that chat (2026-08-16). The entry sits inside “Move to category”, so it is a filing gesture that happens to need a container first — making the category and leaving the chat in its date section was the half-done version of what was asked, and it read as a broken gesture. Naming the category creates it and moves the chat into it in one step; abandoning the name does neither. The same entry in a CATEGORY’s menu (“New subcategory”) has no chat waiting on it and only makes the container.
  • Deleting a category asks first (2026-08-16), in the same modal a chat deletion uses. The menu entry only opens the question. The body repeats the menu’s promise — “the chats stay and return to their date sections” — because “delete” reads as “delete the chats too”, and the modal is where the deletion actually happens.
Still open — not built.
  • Order inside a category. Currently newest first, like everywhere else. A manual order would be a second drag gesture on top of the filing one.
  • Manual order of the categories themselves. The position column exists and is always 0; they list in creation order.
  • Keyboard (ADR-0011). Category rows and section headings are NOT focus items yet, so ← / → keep their meaning as region switches. Rows hidden by a collapse do leave the walk — that comes free, because they are not rendered.
  • Mindmap view. Untouched — the chat/mindmap switch shows the mindmap without categories.
