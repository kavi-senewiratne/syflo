Selecting in the transcript

The transcript is the video's real source text — the counterpart of the PDF page — and it is the only surface in Syflo where a passage cannot yet be selected, highlighted, quoted, or branched from. Decided with the user 2026-08-16: the transcript only (the chapters are the model's own writing, not the source), no time picking while selecting, and the way back leads to both — the passage in the list and the second in the video. Everything after the selection is what the chat and the PDF already do: the same popup, the same five highlight colors, the same “Ask in chat”, the same branch (handleChatSelection, App.tsx). Section 01 is the only real question, and it has three answers.

01 Selecting and jumping on the same rows variant A built

A transcript row is a <button> today: clicking it seeks the player. Dragging a selection across a button fights that click — the same collision the PDF reference links hit in August (“anchors destroy drag selection”), where the fix was a role="button" element instead of a real one. So the row has to give up something. Three ways to decide what.

02 After the selection — nothing new existing

The popup, the five colors, “Ask in chat” and the branch already exist for chat text and PDF text; the transcript simply becomes a third caller of handleChatSelection. The only field that needs a home is the ORIGIN: a transcript passage belongs to a video and to a second in it. That is what makes the way back in §03 possible — and it is recorded automatically from the block the selection starts in, without the reader picking anything.

03 The way back leads to both new

Clicking the quote (or the branch header) does what a PDF quote does — scroll to the passage and flash it — and one thing more, because this source has a time axis: the player seeks to that block's second. The reader lands on the sentence and can immediately hear it. Nothing was asked of them while selecting; the second came from the block the passage started in.

Variant A chosen and built 2026-08-16. The row is a role="button" div with select-text; a click that ends a selection does not seek. Colored marks live in a new transcript_highlights table (video + offsets into the raw transcript + start_seconds of the block), painted as plain React spans rather than through the CSS Custom Highlight API — a transcript block is unformatted text, so slicing it needs no DOM walking.

Chapters were added to the same gesture (user request, same day): their text can be selected, quoted and branched from, while the time chip carries select-none so a drag never drags “07:30” into a question.

Parity round, same day. Chapters became colorable too: the mark then anchors into the OVERVIEW text (parseChapters now reports titleOffset / keyPointOffset) and the row carries source: 'chapter' — one table, two source texts. A mark that opened a branch is clickable and goes to that chat. The way back (showHighlight) switches to the right view, seeks the player and lets the mark glow — brightening upward with a halo, the same movement as the chat's range flash (syflo-mark-flash, 2 × 0.45 s). And a jump no longer wakes a resting player: the IFrame API starts playback from the unstarted state, so every seek on a non-playing player is followed by an explicit pauseVideo.
